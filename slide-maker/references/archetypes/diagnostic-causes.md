# Diagnostic de causes codé

**Répond à :** relier chaque cause établie à l'action qui la traite, pour que
le client voie qu'**aucune recommandation ne tombe du ciel** et qu'aucune cause
n'est laissée sans réponse.

## Anatomie : une grille à trois colonnes, une ligne par cause

| Zone | Part | Contenu |
|---|---|---|
| Titre-message | ~12 % | « Quatre chantiers corrigent 3 causes racines sur 4 » |
| **Cause** | ~30 % | code en pastille (`2a`…`2d`), libellé de la cause, son poids chiffré (« 25 % de l'écart ») |
| **Liaison** | ~5 % | chevron ou flèche fine |
| **Action / chantier** | ~45 % | le chantier qui la traite, verbe d'action en tête, porteur en petit |
| **Effet** | ~20 % | ce que ça corrige (montant, KPI) ; vide = cause non traitée, **dit en toutes lettres** |
| Pied | ~5 % | `Note:` renvoi aux pages de preuve par code |

## Le mécanisme

**Le code est le fil.** La même pastille `2b` apparaît sur la barre du
[bridge](bridge.md) de variance, en tracker de la page de preuve, puis ici en
tête de ligne. Le lecteur suit une cause de la mesure à la solution sans
chercher. Une ligne sans action est une information, pas un oubli : elle se
montre.

## La charge

4 à 6 causes. Au-delà, regrouper par famille (lignes groupées sous une
étiquette pleine) ou scinder.

## Variantes vues

- **Fiche d'annexe « where we want to go / root cause addressed »**
  (McKinsey NCDOT p. 21) : une page par chantier, la cause traitée en encadré.
- **Constats → axes → poids** (RB DGE 2014 p. 11) : constats à gauche, axes de
  recommandation à droite, épaisseur du lien = poids ; comble le passage
  diagnostic → reco qui manque à l'[arbre de résolution](arbre-resolution.md).
- **Matrice d'options polaires** (Strategy& GECOL p. 18 → p. 30) : une ligne par
  cause, deux colonnes d'options opposées (un mot-clé en capitales + une phrase),
  puis la même matrice réduite à l'option retenue avec renvoi aux tâches.
  C'est la version « options » de cette fiche.
- **Tableau priorité × recommandation** (BCG Dallas p. 26) : colonne gauche en
  aplats par famille (mission / initiatives / enablers), recos numérotées.
- **Objectif → KPI** (McKinsey Stop TB) : même grille, mais objectif → indicateur.

## Rendu

- **Paysage** : grille pleine largeur, 3-4 colonnes.
- **Portrait** : une carte par cause, empilées ; dans chaque carte, cause en
  haut (pastille + libellé), action dessous, effet à droite. Le code reste en
  pastille à gauche.

## À ne pas confondre

Avec [acteurs par levier](acteurs-par-levier.md), qui dit **qui** agit. Ici on
dit **pourquoi** cette action : sa cause.
